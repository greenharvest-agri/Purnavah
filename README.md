# Purnavah Order & Invoice System

Catalog-driven order + invoice pipeline for **Greenharvest Agriculture Private Limited (GAPL / Purnavah)**.

`catalog.xlsx` is the single source of truth for every product — name, price, HSN, GST rate, and stock status. One command syncs it out to the customer-facing order form (`index.html`) and the Excel order template. Orders come in either as an Excel sheet or as pasted WhatsApp messages, and are turned into GST-compliant Tax Invoice PDFs (CGST+SGST for Chhattisgarh customers, IGST for everyone else).

## Everyday workflow

Everything below is available from `python\run_all.bat` (just double-click it), or run the scripts directly with `python <script>.py` from inside `python\`.

### Add / edit / discontinue a product

1. Open `catalog.xlsx`, edit the **Catalog** sheet:
   - New product → add a row, set `Active = Y` and `Stock` to a positive number.
   - Out of stock → set `Stock = 0` (it'll auto-flip to `Active = N` next sync and disappear from the form).
   - Price change → edit `MRP`. Takes effect on the form immediately after syncing, and on the *next* invoice run.
2. Run `run_all.bat` → **option 6** (or `python build_form.py` from the repo root).
   This rewrites the product list + category sections in `index.html`, and regenerates `python/orders_template.xlsx` so its columns match the catalog exactly.
3. Commit + push → Netlify redeploys the form automatically.

### Take a WhatsApp order

`run_all.bat` → **option 1** (or `python parse_whatsapp.py`). Paste the WhatsApp order message (the one the order form itself generates), then finish input with `Ctrl+Z` then `Enter`. It matches each line item against the catalog's **WA Key** (auto-generated as `"<Display Name> (<Pack Size>)"`), pulls out the delivery details, and appends a row to `orders.xlsx` (created from `orders_template.xlsx` on first use).

### Generate invoices

- **All customers:** `run_all.bat` → option 2, or `python generate_invoices.py`
- **One customer:** option 3, or `python generate_invoices.py --customer "Name"`

PDFs are written to `python/invoices/` as `Invoice_<CustomerName>.pdf`, one per row in `orders.xlsx`.

## catalog.xlsx schema

Sheet name: **Catalog**

| Column | Purpose |
|---|---|
| `Product Name` | Internal key — also the column header used in `orders.xlsx` |
| `Category` | Groups products into sections on the order form |
| `Display Name` | Customer-facing name shown on the form and in WhatsApp messages |
| `Unit` | `L`, `kg`, `ml`, `box`, etc. — shown on invoices |
| `Pack Size` | e.g. `1 L`, `500 g` — combined with Display Name to build the WA Key |
| `MRP` | Selling price (₹), used for both the form and invoices |
| `HSN/SAC` | HSN code, printed on invoices |
| `GST%` | GST rate applied on invoices |
| `Stock` | Set to `0` to auto-deactivate a product |
| `Active` | `Y`/`N` — only `Y` rows with `Stock > 0` appear on the order form |
| `WA Key` | Auto-generated by `build_form.py` — **never edit by hand** |
| `Notes` | Free text, not used programmatically |

## Tax logic

Company is registered in **Chhattisgarh (state code 22)**.

| Customer state | Tax applied |
|---|---|
| Chhattisgarh (code `22`) | CGST + SGST, half the GST rate each |
| Any other state | IGST at the full GST rate |

State is resolved per customer as: GSTIN prefix → `Place of Contact` code → `Billing State` name lookup (see `get_state_code()` in `python/generate_invoices.py`).

## Customers file (Zoho export format)

`generate_invoices.py` auto-detects the customer sheet and these columns by keyword (exact Zoho export names work out of the box):

| Column | Purpose |
|---|---|
| `Display Name` | Matched against `orders.xlsx`'s `Customer Name` column |
| `Billing Address` / `City` / `State` / `Code` | Bill To address |
| `Shipping Address` … | Ship To address (falls back to billing if blank) |
| `GST Identification Number (GSTIN)` | Shown on invoice; first 2 digits = state code |
| `Place of Contact` | 2-letter state code (e.g. `CG`, `MH`) used when GSTIN is absent |

Name matching priority: `NAME_MAPPING` override (top of `generate_invoices.py`) → exact match → case-insensitive → prefix match → first-name match. Unmatched customers are skipped with a warning.
